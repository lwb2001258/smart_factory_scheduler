# 碰撞、重规划与停滞修复工作流

本文定义碰撞逻辑修复的实施和验收流程。目标是保证任意时刻机器人实际执行路径、Supervisor 活动计划、空间预约、时间预约和路径版本保持一致，并消除重复重规划、合法等待误判停滞及非必要物理迁移。

## 执行原则

每个步骤必须完整执行以下闭环，未通过不得进入下一步：

1. 实现当前步骤的最小完整变更。
2. 第一轮 Code Review：检查状态事务、失败回滚、调用链和异常路径。
3. 根据第一轮意见修正。
4. 运行当前步骤的定向测试和全部已有回归测试。
5. 第二轮 Code Review：检查并发时序、版本一致性、性能、指标及与其他恢复层的交互。
6. 根据第二轮意见修正。
7. 再次运行定向测试、全量测试和静态编译。
8. 在本文记录验证结果后进入下一步。

## 实施步骤

### 步骤 1：预约事务安全

- 重规划采用候选状态，不得在候选成功前破坏活动预约。
- 规划失败、异常和派发失败后，旧路径及预约保持不变。
- 验证同一机器人重复规划和不同机器人并发候选。

### 步骤 2：最终路径与预约一致

- 所有车道调整、转折保留和抽样必须在预约生成前完成。
- 从最终下发折线重新生成连续栅格。
- 出发延迟只允许取所有约束的最大值。
- 最终延迟确定后生成时间预约。

### 步骤 3：版本化派发

- 所有 navigate、hold 和恢复移动通过统一派发入口。
- Supervisor 是路径版本唯一生成者。
- 状态上报携带控制器活动版本和航点索引。
- 旧版本命令不得覆盖新版本。

### 步骤 4：统一时间轴和实时预测

- 资源预约全部使用绝对仿真秒。
- 过期预约按仿真秒清理。
- 预测从真实位置和剩余航点开始，并纳入 pending、hold、紧急停车和实测速度。

### 步骤 5：停滞与恢复

- 只有应当移动的机器人累计停滞时间。
- 合法预约等待、hold、待激活路径和紧急制动分别记录。
- 后退恢复使用版本化、安全校验路径。
- 非物理迁移默认退出正式实验链，仅保留显式调试开关。

### 步骤 6：系统回归

- 运行静态编译、全部单元测试、确定性冲突场景和独立仿真冒烟测试。
- 检查活动路径版本、预约覆盖、延迟单调性、无进展恢复和指标完整性。

## 硬性验收条件

- 候选规划失败后活动预约不变。
- 最终执行折线经过的全部栅格均包含在该计划的空间预约中。
- 最终出发时间不早于任一冲突约束。
- Supervisor 与控制器活动路径版本一致。
- hold 或 pending 状态不会被普通停滞监控误判。
- 正式实验不依赖物理迁移完成任务。
- 每种重规划结果均记录成功、失败、回滚或重复路径原因。
